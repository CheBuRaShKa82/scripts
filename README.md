# 🛡️ VPS Setup Scripts

Набор Bash-скриптов для быстрой первоначальной настройки безопасности и рабочего окружения на **Ubuntu / Debian VPS** с `systemd`:

- 🔐 базовое усиление безопасности сервера (`secure-vps.sh`);
- 🐳 автоматическая установка Docker Engine и Docker Compose из официального репозитория Docker (`install-docker.sh`);
- 🤖 установка платформы автоматизации **n8n** с PostgreSQL, HTTPS и базовой защитой сервера одним скриптом (`install-n8n-vps.sh`).

---

## 📦 Содержимое репозитория

| Скрипт | Назначение |
|---|---|
| `secure-vps.sh` | Интерактивная базовая защита VPS: отдельный пользователь, SSH, UFW, Fail2Ban, sysctl, Telegram и двухэтапная проверка с автооткатом |
| `install-docker.sh` | Автоматическая установка Docker Engine, Buildx и Compose Plugin для Ubuntu / Debian |
| `install-n8n-vps.sh` | Установка n8n на чистый VPS: Docker Compose, PostgreSQL, Caddy с автоматическим SSL, SSH, UFW, Fail2Ban, ежедневные бэкапы |

# 🔐 secure-vps.sh

Интерактивный скрипт для базовой защиты нового VPS с защитой от потери доступа (двухэтапная проверка подключения и автооткат при ошибке).

## Что настраивает скрипт

- **Администратор**: создание отдельного пользователя в группе `sudo` с обязательным паролем (не менее 12 символов).
- **SSH**: запрет входа под `root`, ограничение доступа через `AllowUsers`, сменяемый порт, вход только по SSH-ключу (рекомендуется) или паролю.
- **Firewall (UFW)**: закрытие всех входящих соединений по умолчанию; при сбросе UFW остаётся разрешён только выбранный SSH-порт, а при отказе существующие правила сохраняются и добавляется новый SSH-порт.
- **Fail2Ban**: защита SSH от подбора паролей с добавлением вашего IP в белый список и постепенным увеличением времени блокировки.
- **Telegram**: отправка оповещений об успешном SSH-входе и блокировках IP через Fail2Ban.
- **Система**: применение базовых защитных параметров ядра `sysctl` и опциональная активация автоматических обновлений безопасности (`unattended-upgrades`).

---

## ⚠️ Что подготовить перед запуском

- **Telegram-бот**: создайте бота в [@BotFather](https://t.me/BotFather) и узнайте числовой `TG_CHAT_ID` (например, через [@userinfobot](https://t.me/userinfobot)). Токен и ID чата обязательны для запуска мастера.
- **SSH-ключ**: подготовьте ваш публичный ключ при выборе входа по ключу (скрипт также может импортировать подходящие ключи из `/root/.ssh/authorized_keys`).
- **Панель хостинга**: если у VPS-провайдера включен внешний Firewall / Security Group, заранее разрешите выбранный SSH-порт.
- **Сессия терминала**: держите текущую сессию открытой до завершения всех проверок.

---

## 🚀 Запуск и порядок работы мастера

> [!IMPORTANT]
> `secure-vps.sh` необходимо запускать от `root` или через `sudo` в интерактивном терминале.
> Запуск через `curl ... | bash`, CI/CD или stdin без TTY не поддерживается.

```bash
git clone https://github.com/CheBuRaShKa82/scripts.git
cd scripts
chmod +x secure-vps.sh install-docker.sh
sudo ./secure-vps.sh
```

### Порядок работы мастера:

1. **Сбор параметров:** скрипт последовательно запрашивает токен Telegram, `TG_CHAT_ID`, имя администратора, способ SSH-аутентификации, пароль пользователя для `sudo` (не менее 12 символов), порт SSH, IP для белого списка Fail2Ban, автообновления и режим сброса правил UFW.
2. **Подтверждение:** выводится сводная таблица всех указанных параметров, после чего требуется ввести `YES` для продолжения.
3. **Тест Telegram:** скрипт проверяет возможность отправки тестового сообщения. Если Telegram API временно недоступен, скрипт выведет предупреждение и продолжит настройку.
4. **Применение SSH и первая проверка:** создаётся пользователь, настраиваются SSH, PAM и Fail2Ban, после чего скрипт ожидает проверки подключения во втором окне терминала (таймаут 5 минут).
5. **Настройка UFW и вторая проверка:** настраивается firewall и выполняется повторная проверка SSH-доступа во избежание блокировки (таймаут 5 минут).

## 📲 Telegram

Для запуска необходимо указать:

- `Telegram Bot Token`;
- числовой `TG_CHAT_ID`.

Перед применением основных изменений скрипт проверяет возможность отправки тестового сообщения.

Если Telegram API временно недоступен, скрипт выведет предупреждение и продолжит настройку.

После установки Telegram используется для уведомлений:

- об успешном SSH-входе;
- о блокировке IP через Fail2Ban.

---

## 🧯 Защита от потери доступа (Rollback)

В процессе настройки предусмотрены две обязательные проверки SSH с таймаутом 5 минут.

1. **После изменения SSH:** необходимо подключиться в новом окне по новому порту, проверить `sudo` и Telegram-уведомление.
2. **После настройки UFW:** необходимо повторно проверить SSH-доступ через firewall.

> [!IMPORTANT]
> Если первая проверка не пройдена, скрипт выполняет полный откат внесённых изменений, включая SSH-конфигурацию и созданного пользователя.
>
> После успешной первой проверки новый пользователь и SSH-настройки считаются рабочими. Если проблема возникает на финальном этапе настройки UFW, скрипт откатывает настройки firewall, сохраняя рабочий SSH-доступ.

# 🐳 install-docker.sh

Автоматический установщик Docker Engine, Buildx и Docker Compose Plugin для **Ubuntu** и **Debian**.

Скрипт определяет дистрибутив через `/etc/os-release`, проверяет архитектуру и подключает официальный репозиторий Docker.

## Что устанавливается

- `docker-ce`
- `docker-ce-cli`
- `containerd.io`
- `docker-buildx-plugin`
- `docker-compose-plugin`

---

## 🚀 Установка Docker

```bash
chmod +x install-docker.sh
sudo ./install-docker.sh
```

Скрипт выполняет следующие шаги:

1. Удаляет конфликтующие пакеты (`docker.io`, `containerd`, `podman-docker` и др.).
2. Устанавливает зависимости `ca-certificates` и `curl`.
3. Добавляет официальный GPG-ключ Docker и настраивает репозиторий в `/etc/apt/sources.list.d/docker.sources`.
4. Устанавливает официальный Docker Engine, Buildx и Compose Plugin.
5. Включает и запускает службу Docker через `systemd`.
6. При интерактивном запуске через `sudo` предлагает добавить пользователя, от имени которого был вызван `sudo`, в группу `docker` для запуска без `sudo`.

---

## ⚠️ Docker и UFW

> [!WARNING]
> Docker по умолчанию управляет цепочками `iptables` напрямую в обход правил UFW. Опубликованный контейнером порт (например, `-p 8080:8080`) может оказаться доступен извне даже при политике `ufw default deny incoming`.

- Для локальных сервисов публикуйте порты только на интерфейсе loopback: `127.0.0.1:8080:8080`.
- Для централизованного ограничения доступа извне используйте цепочку `DOCKER-USER` в `iptables`.

# 🤖 install-n8n-vps.sh

Интерактивный установщик **n8n** на чистый VPS (Ubuntu / Debian). За один запуск разворачивает рабочую панель по HTTPS на вашем (под)домене, защищает сервер и настраивает автоматические бэкапы. Поддерживаются домены в зоне `.ru`, `.рф` и любые другие (кириллические имена автоматически преобразуются в punycode).

## Что устанавливается

| Компонент | Описание |
|---|---|
| **n8n** | Образ `docker.n8n.io/n8nio/n8n` (версия выбирается при запуске, по умолчанию `latest`) |
| **PostgreSQL 18** | Выделенный контейнер (не SQLite). Доступен только во внутренней docker-сети, наружу порт не публикуется |
| **Caddy 2** | Reverse proxy с автоматическим выпуском и продлением сертификата Let's Encrypt, HTTP/3, заголовки безопасности (HSTS и др.) |
| **Docker Engine + Compose** | Устанавливается из официального репозитория, если ещё не установлен (при недоступности — запасной вариант из репозитория системы) |

## Что настраивает скрипт

- **n8n**: User Management (владелец создаётся при первом входе), `N8N_ENCRYPTION_KEY`, часовой пояс, отключённая телеметрия.
- **Диск**: автоочистка истории выполнений (`EXECUTIONS_DATA_PRUNE=true`, хранение 48 часов, значение меняется в `.env`).
- **Отказоустойчивость**: `restart: unless-stopped` для всех контейнеров, healthcheck'и и порядок запуска (`depends_on`), ротация логов контейнеров.
- **Администратор** (по желанию): отдельный пользователь в группе `sudo` с входом по SSH-ключу (рекомендуется) или по паролю. Пароль можно задать вручную или сгенерировать автоматически.
- **SSH**: смена порта с безопасной двухэтапной миграцией и автооткатом; после проверки входа можно отключить вход под `root` (и вход по паролю, если выбран вход по ключу).
- **Firewall (UFW)**: закрыты все входящие соединения, кроме выбранного SSH-порта (с ограничением частоты подключений), `80/tcp`, `443/tcp` и `443/udp`.
- **Fail2Ban**: защита SSH от подбора (5 неудачных попыток за 10 минут — блокировка на 1 час).
- **Бэкапы**: ежедневно в 03:15 (`cron`), дамп PostgreSQL + данные n8n + `.env` в `/var/backups/n8n-*`, хранится 7 последних копий.
- **Файл доступов**: `/root/n8n-credentials.txt` (права `600`) со всеми паролями, ключом шифрования и командами управления.

---

## ⚠️ Что подготовить перед запуском

- **VPS**: чистый сервер с Ubuntu 24.xx / 26.xx или Debian 12 / 13, минимум 2 vCPU и 2 ГБ RAM (рекомендуется 4 ГБ).
- **DNS**: `A`-запись поддомена (например, `n8n.example.ru`) должна указывать на IP сервера. Без неё Let's Encrypt не выдаст сертификат. Скрипт сам сверяет запись с публичным IP и предупреждает о несовпадении или наличии `AAAA`.
- **Порты**: `80` и `443` должны быть свободны (скрипт остановится, если их занимает посторонний процесс).
- **E-mail** для уведомлений Let's Encrypt.
- **Панель хостинга**: если у провайдера включён внешний Firewall / Security Group, откройте в нём новый SSH-порт, `80/tcp`, `443/tcp` и `443/udp`.
- **Сессия терминала**: держите текущую сессию открытой до завершения всех проверок.

---

## 🚀 Запуск и порядок работы мастера

> [!IMPORTANT]
> `install-n8n-vps.sh` необходимо запускать от `root` или через `sudo` в интерактивном терминале.
> Запуск через `curl ... | bash`, CI/CD или stdin без TTY не поддерживается.

```bash
chmod +x install-n8n-vps.sh
sudo ./install-n8n-vps.sh
```

### Порядок работы мастера:

1. **Сбор параметров:** домен, e-mail для Let's Encrypt, новый SSH-порт (по умолчанию `5040`; допустимы `1024–65535`, кроме `22`, `5432`, `5678`), часовой пояс, версия n8n. Затем — создание администратора: способ входа (пароль или SSH-ключ) и сам пароль (свой или автоматически сгенерированный).
2. **Подтверждение:** выводится сводка (домен, SSH-порт), после чего требуется подтвердить начало установки.
3. **Подготовка:** установка пакетов и Docker, проверка занятости портов `80/443`, проверка DNS, создание `.env`, `compose.yaml`, `Caddyfile` и их валидация.
4. **Firewall и SSH:** настраивается UFW, SSH временно слушает **старый и новый** порты. Скрипт просит проверить вход по новому порту во втором окне терминала и только после подтверждения закрывает старый порт.
5. **Защита SSH (по желанию):** после проверки входа под новым пользователем скрипт предлагает отключить вход под `root` (при входе по ключу — также вход по паролю).
6. **Запуск стека:** скачиваются образы, контейнеры запускаются и ожидается состояние `healthy`, затем проверяются PostgreSQL и HTTPS.

> [!NOTE]
> Если выбран автоматически сгенерированный пароль, он показывается на экране сразу после создания пользователя — сохраните его до проверки входа. В конце установки он также записывается в файл доступов.

---

## 🧯 Защита от потери доступа и повторные запуски

- **Двухэтапная миграция SSH-порта.** Пока вы не подтвердите вход по новому порту, старый порт остаётся доступным. Если новый порт не поднялся, старый пропал раньше времени или вход не подтверждён — скрипт восстанавливает исходные SSH-конфиги.
- **Ubuntu 24.04 и `ssh.socket`.** На Ubuntu 24.04 SSH запускается через socket-активацию, которая игнорирует `Port` из `sshd_config`. Скрипт отключает `ssh.socket` и запускает обычный `ssh.service`, чтобы порт менялся корректно.
- **Повторный запуск безопасен.** `POSTGRES_PASSWORD` и `N8N_ENCRYPTION_KEY` из существующего `.env` сохраняются, перед обновлением конфигурации создаётся резервная копия `/opt/n8n.backup-*` (хранятся 5 последних).
- **Защита от потери ключа шифрования.** Если найдены volumes n8n/PostgreSQL, но `.env` отсутствует, скрипт остановится и не станет генерировать новые секреты.

> [!IMPORTANT]
> `N8N_ENCRYPTION_KEY` нужен для расшифровки сохранённых credentials. Сохраните ключ из `/root/n8n-credentials.txt` отдельно от сервера: без него данные в n8n не восстановить.

## ✅ После установки

1. Откройте `https://ваш-поддомен/` и **сразу создайте владельца (Owner)** n8n, пока панель не нашли посторонние.
2. Перенесите `/root/n8n-credentials.txt` в менеджер паролей и удалите файл с сервера.
3. Копируйте бэкапы из `/var/backups` за пределы VPS или подключите снапшоты у провайдера.

### Управление стеком

```bash
cd /opt/n8n
docker compose restart                              # перезапуск
docker compose pull && docker compose up -d         # обновление n8n
docker compose logs -f --tail=100                   # логи
sudo /opt/n8n/backup.sh                             # ручной бэкап
```

Если версия закреплена (не `latest`), перед обновлением измените `N8N_VERSION` в `/opt/n8n/.env`.

### Файлы на сервере

| Путь | Назначение |
|---|---|
| `/opt/n8n/.env` | Секреты и параметры (домен, пароль БД, ключ шифрования, срок хранения executions) |
| `/opt/n8n/compose.yaml` | Описание стека (n8n, PostgreSQL, Caddy) |
| `/opt/n8n/Caddyfile` | Конфигурация reverse proxy |
| `/opt/n8n/backup.sh` | Скрипт бэкапа (запускается по cron) |
| `/var/backups/n8n-*` | Бэкапы (дамп БД, данные n8n, `.env`) |
| `/root/n8n-credentials.txt` | Все доступы и команды управления |
| `/var/log/n8n-installer.log` | Лог установщика |

## 🔎 Особенности и ограничения

- **Docker и UFW.** Опубликованы только `80`, `443/tcp` и `443/udp`; PostgreSQL и n8n находятся во внутренней docker-сети и снаружи недоступны.
- **Отличия от `secure-vps.sh`.** Установщик n8n делает собственную базовую защиту (SSH, UFW, Fail2Ban), но не отправляет Telegram-уведомления, не применяет `sysctl` и не настраивает `AllowUsers`. Для чистого сервера достаточно одного `install-n8n-vps.sh`.
- **Совместное использование с `secure-vps.sh`.** Если сервер уже защищён через `secure-vps.sh`, укажите в мастере тот же SSH-порт, который сейчас используется, и откажитесь от создания нового пользователя. Такая комбинация не тестировалась — проверьте её на тестовом сервере.
- **Версия n8n.** Тег `latest` плавающий: для production рекомендуется зафиксировать конкретную версию.
- **Самопроверка.** `sudo ./install-n8n-vps.sh --self-test` проверяет только внутренние функции валидации (домен, порт, e-mail) и ничего не меняет в системе.

## 🖥 Поддерживаемые системы

Скрипты рассчитаны на:

- **Ubuntu** и **Debian** с `systemd` (`install-n8n-vps.sh`: Ubuntu 24.xx / 26.xx и Debian 12 / 13);
- пакетный менеджер `apt` и OpenSSH.

Скрипты **не предназначены** для систем семейств RHEL (CentOS, Rocky Linux, AlmaLinux), Alpine Linux или Arch Linux.

## 📋 Рекомендуемый порядок настройки нового сервера

1. **Базовая защита сервера:**
   ```bash
   sudo ./secure-vps.sh
   ```
2. **Переподключение под новым администратором:**
   ```bash
   ssh -p PORT USERNAME@SERVER_IP
   ```
3. **Установка Docker:**
   ```bash
   sudo ./install-docker.sh
   ```
4. **Открытие портов веб-сервера (при необходимости):**
   ```bash
   sudo ufw allow 80/tcp
   sudo ufw allow 443/tcp
   ```

> [!TIP]
> Если вам нужен только n8n, пропустите шаги 1–4: `install-n8n-vps.sh` сам установит Docker, настроит SSH, UFW и Fail2Ban и запустит n8n на вашем домене.

5. **Установка n8n (опционально):**
   ```bash
   sudo ./install-n8n-vps.sh
   ```

## 🔎 Полезные команды

| Задача | Команда |
|---|---|
| Проверка статуса UFW | `sudo ufw status verbose` |
| Список правил UFW с номерами | `sudo ufw status numbered` |
| Статус защиты Fail2Ban | `sudo fail2ban-client status sshd` |
| Проверка эффективного конфига SSH | `sudo sshd -T` |
| Проверка работы Docker | `sudo docker run --rm hello-world` |
| Список активных контейнеров | `sudo docker ps` |
| Статус службы Docker | `sudo systemctl status docker` |
| Логи службы SSH | `sudo journalctl -u ssh` |
| Статус контейнеров n8n | `cd /opt/n8n && docker compose ps` |
| Логи n8n | `cd /opt/n8n && docker compose logs -f --tail=100 n8n` |
| Перезапуск n8n | `cd /opt/n8n && docker compose restart` |
| Обновление n8n | `cd /opt/n8n && docker compose pull && docker compose up -d` |
| Ручной бэкап n8n | `sudo /opt/n8n/backup.sh` |
