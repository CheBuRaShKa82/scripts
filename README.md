# 🛡️ VPS Setup Scripts

Набор Bash-скриптов для быстрой первоначальной настройки и защиты серверов на базе **Ubuntu / Debian**:

- 🔐 базовое усиление безопасности сервера (SSH, UFW, Fail2Ban, sysctl);
- 👤 создание отдельного администратора с правами `sudo`;
- 📲 обязательные Telegram-уведомления о входах и блокировках;
- 🐳 установка актуального Docker Engine и Docker Compose Plugin из официального репозитория.

> Скрипты предназначены для чистых VPS на **Ubuntu** или **Debian** с системой инициализации `systemd`.

---

## 📦 Что входит в репозиторий

| Скрипт | Назначение | Режим работы |
|---|---|---|
| `secure-vps.sh` | Первоначальная настройка безопасности: новый пользователь, SSH, UFW, Fail2Ban, sysctl, Telegram и автоматический откат при ошибках | Интерактивный визард |
| `install-docker.sh` | Установка Docker Engine, Buildx и Docker Compose Plugin из официального репозитория Docker | Автоматический |

# 🔐 secure-vps.sh

Интерактивный скрипт для базового закрытия и защиты сервера. Скрипт ориентирован на максимальную безопасность: перед внесением изменений создаются резервные копии, а в процессе настройки предусмотрен **автоматический откат (rollback)**, если что-то пойдет не так или вы потеряете SSH-доступ.

## Что настраивает скрипт

- **Администратор**: создание выделенного пользователя, добавление в группу `sudo`, обязательный надежный пароль (от 12 символов).
- **SSH**:
  - отключение прямого входа под `root` (`PermitRootLogin no`);
  - ограничение круга пользователей через директиву `AllowUsers`;
  - смена стандартного порта (по умолчанию на `22222`);
  - выбор авторизации: строгий SSH-ключ (рекомендуется) или надежный пароль;
  - отключение перенаправления X11 и агентов.
- **Firewall (UFW)**: политика по умолчанию — запретить все входящие соединения (`deny incoming`), разрешить исходящие и открыть только выбранный порт SSH.
- **Fail2Ban**: автоматический джейл для SSH с белым списком вашего IP, динамическим увеличением времени бана и интеграцией с UFW.
- **Telegram**: оповещения в реальном времени при каждом успешном SSH-входе и блокировке атакующих через Fail2Ban.
- **Ядро и обновления**: базовые защитные сетевые параметры `sysctl` и автоматические обновления безопасности (`unattended-upgrades`).

## ⚠️ Что подготовить перед запуском

1. **Telegram-бот (обязательно):**
   - Создайте бота через [@BotFather](https://t.me/BotFather) и скопируйте **Bot Token**.
   - Узнайте свой числовой ID чата (например, через [@userinfobot](https://t.me/userinfobot)).
   - Нажмите `/start` в диалоге с созданным ботом.
2. **SSH-ключ:**
   - Если планируется вход по ключу, скрипт может автоматически взять существующий ключ из `/root/.ssh/authorized_keys` или попросит вставить публичный ключ вручную.
3. **Панель хостинга:**
   - Если у вашего хостинг-провайдера есть внешний фаервол (Security Groups / Firewall), **заранее откройте там выбранный TCP-порт SSH** (по умолчанию `22222`).
4. **Сессия подключения:**
   - Не закрывайте текущую сессию терминала, пока скрипт полностью не завершит работу!

## 🚀 Запуск и интерактивные шаги

Клонируйте репозиторий и сделайте скрипты исполняемыми:

```bash
git clone https://github.com/CheBuRaShKa82/scripts.git
cd scripts
chmod +x secure-vps.sh install-docker.sh
```

Запустите скрипт защиты от имени суперпользователя:

```bash
sudo ./secure-vps.sh
```

Скрипт пошагово запросит параметры:
1. `Telegram Bot Token` и `TG_CHAT_ID` (сразу отправит тестовое сообщение для проверки связи);
2. Имя нового пользователя-администратора (по умолчанию `admin`);
3. Способ входа по SSH (вариант `1` — по ключу, `2` — по паролю);
4. Пароль для нового пользователя (используется для выполнения команд через `sudo`);
5. Новый SSH-порт (по умолчанию `22222`);
6. IP/подсеть для белого списка Fail2Ban (текущий IP определяется автоматически);
7. Включение автообновлений безопасности;
8. Необходимость сброса существующих правил UFW (если фаервол уже был активен).

## 🧯 Защита от потери доступа (Rollback)

В процессе работы скрипт делает две контрольные паузы (таймаут ожидания — 5 минут на каждую):

1. **После настройки SSH:** скрипт попросит открыть **новое окно терминала** и подключиться к серверу по новому порту с созданным логином:
   ```bash
   ssh -p PORT USER@SERVER_IP
   ```
2. **После окончательного включения UFW:** финальная проверка связности через фаервол.

> Если в любом из тестов подключение не удалось, сессия оборвалась или вы ввели что-либо кроме `YES`, скрипт **автоматически вернет все системные файлы к исходному состоянию** и восстановит настройки сети.

---

## ✅ Проверка безопасности

После успешного выполнения переподключитесь новым пользователем:

```bash
ssh -p 22222 admin@IP_СЕРВЕРА
```

Проверьте статус компонентов:

```bash
# Статус фаервола
sudo ufw status verbose

# Статус защиты Fail2Ban
sudo fail2ban-client status sshd

# Проверка применения параметров OpenSSH
sudo sshd -T | grep -Ei '^(port|permitrootlogin|allowusers)'
```

# 🐳 install-docker.sh

Скрипт для быстрой установки актуального Docker Engine, Buildx и Docker Compose Plugin из официального репозитория Docker.

## Что устанавливается

- `docker-ce`
- `docker-ce-cli`
- `containerd.io`
- `docker-buildx-plugin`
- `docker-compose-plugin`

---

## 🚀 Установка Docker

Выполните скрипт:

```bash
sudo ./install-docker.sh
```

Скрипт в автоматическом режиме:
1. Определит дистрибутив (Ubuntu или Debian), архитектуру и кодовое имя репозитория;
2. Удалит потенциально конфликтующие пакеты сторонних сборок;
3. Добавит официальный GPG-ключ и репозиторий `download.docker.com`;
4. Установит компоненты Docker и плагин `docker compose`;
5. Запустит и включит службу через `systemd`;
6. При интерактивном запуске предложит добавить текущего пользователя в группу `docker` (для работы без постоянного вызова `sudo`).

---

## ✅ Проверка Docker

Тестовый запуск контейнера:

```bash
sudo docker run --rm hello-world
```

Проверка версий:

```bash
docker --version
docker compose version
```

Статус службы:

```bash
sudo systemctl status docker
```

# ⚠️️ Важно: Docker и UFW

По умолчанию демон Docker напрямую управляет правилами `iptables`, в обход стандартных цепочек UFW. Это означает, что если контейнер публикует порт наружу (например, `-p 8080:8080`), этот порт может оказаться открыт для всего мира даже при включенном `ufw default deny incoming`.

**Рекомендации:**
- Если сервис должен работать только локально (например, за Nginx/Traefik или для служебных баз данных), привязывайте порт строго к `127.0.0.1`:
  ```bash
  docker run -p 127.0.0.1:8080:8080 my-image
  ```
  В `docker-compose.yml`:
  ```yaml
  ports:
    - "127.0.0.1:8080:8080"
  ```
- Для ограничения внешнего доступа к опубликованным портам Docker настраивайте правила через цепочку `DOCKER-USER`.

# 🖥 Поддерживаемые системы

Скрипты предназначены исключительно для систем с пакетным менеджером `apt` и `systemd`:

- **Ubuntu** (20.04 LTS, 22.04 LTS, 24.04 LTS и новее);
- **Debian** (11 Bullseye, 12 Bookworm и новее).

Скрипты **не предназначены** для CentOS, RHEL, AlmaLinux, Alpine, Arch Linux или систем без `systemd`.

# 📋 Рекомендуемый порядок действий на новом сервере

1. **Подключитесь к VPS под `root`:**
   ```bash
   ssh root@SERVER_IP
   ```

2. **Склонируйте репозиторий и настройте безопасность:**
   ```bash
   git clone https://github.com/CheBuRaShKa82/scripts.git
   cd scripts
   chmod +x secure-vps.sh install-docker.sh
   sudo ./secure-vps.sh
   ```

3. **Подключитесь в новой сессии созданным администратором:**
   ```bash
   ssh -p 22222 admin@SERVER_IP
   ```

4. **Установите Docker:**
   ```bash
   cd scripts
   sudo ./install-docker.sh
   ```

5. **Откройте необходимые сервисные порты (при необходимости):**
   ```bash
   # Например, для веб-сервера
   sudo ufw allow 80/tcp
   sudo ufw allow 443/tcp
   ```

# 🔎 Шпаргалка по полезным командам

| Задача | Команда |
|---|---|
| Проверка синтаксиса SSH-конфига | `sudo sshd -t` |
| Просмотр действующих параметров SSH | `sudo sshd -T` |
| Просмотр логов SSH | `sudo journalctl -u ssh` |
| Состояние правил UFW с номерами | `sudo ufw status numbered` |
| Разблокировать IP в Fail2Ban | `sudo fail2ban-client unban <IP>` |
| Просмотреть статус джейла Fail2Ban | `sudo fail2ban-client status sshd` |
| Проверить список контейнеров Docker | `docker ps` |
